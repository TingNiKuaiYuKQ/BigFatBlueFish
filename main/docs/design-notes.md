## 原始 README

一个独立的 Windows 桌面 Live2D 桌宠，能被 DeepSeek Harness（DSH）的会话状态驱动——

**AI 在思考、在写文件、在跑命令、出错了，她会用表情和姿势同步反应；需要说话时，模型调一个工具让她冒气泡。**

和 B 站 [BV1aUxE6kEW4](https://www.bilibili.com/video/BV1aUxE6kEW4)（FULASKA 的「大肥鱼 Live2D 桌宠」）是**两个独立实现**。这里只在 Live2D 渲染方案、窗口/事件处理等关键做法上参考了它（MIT），没有复制它的程序。两者可以同时用，互不干扰（都读同一个 `~/.dsh/live2d/`）。

## 快速开始

### 1. 启动桌宠（独立运行，不需要 DSH）

两种方式，都不依赖系统装 Node：

| 方式 | 说明 |
|---|---|
| 双击 **`启动桌宠.cmd`**（仓库根目录） | 最省事的入口，直连下面的启动脚本 |
| 双击 `pet/stage/start.cmd` | 带控制台，看日志方便 |
| `node launch.mjs` | 开发用，参数透传最方便（这个要 Node） |

> 旧版用 `.vbs` 中转入口，但部分机器禁用了 WSH/VBScript，`.vbs` 无法双击运行，
> 已改为 `.cmd`。本机若仍打不开，右键「以管理员身份运行」或改用 `node launch.mjs`。

**start.cmd 统一走 `launch.mjs`，不要直接跑 electron.exe**：electron.exe 被系统策略挡住
写不了 `~/.dsh/live2d/endpoint.json`（EPERM），握手镜像只能由 node 启动器做 ——
直接跑 electron 的话桌宠能显示，但 DSH 插件永远找不到它。系统没装 Node 时 start.cmd
会退回直接启动并明确提示「STANDALONE 模式」（此时独立桌宠功能完整，只是接不上 DSH）。

首次启动会自动压缩贴图（8192² → 2048²，约 1 秒），之后复用。

| 操作 | 效果 |
|---|---|
| 左键拖动角色 | 移动窗口 |
| 左键点角色 | 随机换个表情 + 冒一句 |
| 右键角色 | 菜单：**表情 / 姿势** / 设置文件 / 状态文件 / 鼠标穿透 / 退出 |
| `Ctrl+Alt+L` | 切换鼠标穿透 |
| `Ctrl+Alt+Q` | 退出 |

右键菜单里是完整的 **23 个表情 + 4 个姿势**，不接 DSH 也能全部切换——这是它作为独立桌宠的自我交互层。

### 2. 接入 DSH（可选）

```bash
cd pet
node install.mjs            # 先预览要改什么
node install.mjs --apply    # 真正写入（会先备份 profile）
cd ~/.dsh/profiles/desktop && pnpm install
```

然后重启 DSH。验证：`~/.dsh/live2d/status.json` 应该出现（`state: null` 表示空闲）。

之后随便让 DSH 干点活，她会跟着变脸。

### 3. 快捷指令

编辑 `~/.dsh/live2d/shortcuts.json`（首次运行会从 `pet/shortcuts.json` 复制过去），改完重启桌宠。

## 独立性：它到底依赖什么

一句话：**桌宠本体完全独立，DSH 只是一个可选的「驾驶员」。**

这不是推测，是实测——把 `USERPROFILE` 指到一个全新空目录（等价于一台没装过 DSH 的机器）再启动：

| 检查项 | 结果 |
|---|---|
| 模型载入 | ✓ 3749×7697，23 个表情扫到 |
| 窗口 | ✓ 700×1365 物理像素（贴合模型），120fps |
| 待机状态 | ✓ `状态 idle → 表情 默认体型 姿势 default` |
| 拖动 80 次 | ✓ 尺寸零变化、resize 0 次 |
| 空目录副作用 | ✓ 一个文件都没创建 |

### 依赖清单

| 项 | 算外部程序吗 | 说明 |
|---|---|---|
| Electron 运行时 | 否 | 就在 `pet/stage/node_modules/electron/dist/`，跟着目录走 |
| Node.js | 否 | `start.cmd` 不需要；只有 `launch.mjs` 要 |
| **DSH** | **可选** | 作用是「把会话状态翻译成表情」。不装就是普通桌宠 |
| 模型 | 否 | 它自己的资源，放 `model/` 或 `<stage>/model` 都行 |
| Windows | 是 | 目标平台 |

### 驾驶员这一层做了什么

两条通道，都不影响桌宠单独运行：

1. **正向（DSH → 桌宠）**：插件把会话状态归约后原子写 `status.json`，桌宠每 200ms 轮询读。
   **文件不存在 = 按 idle 处理**，这是默认路径，不是异常。
2. **反向（桌宠 → DSH）**：桌宠启动时写 `endpoint.json`，告诉插件端口和 token。
   **目标目录不存在就直接跳过**，不会凭空去建 `~/.dsh/live2d` 这种属于别人的目录。
   跳过也不影响后续——一旦状态文件出现（说明驾驶员上线了），桌宠会自动补写握手。
   所以「先开桌宠」还是「先装插件」都不影响结果，不用重启。

关掉驾驶员有两种方式：

```bash
# 临时：命令行压掉，配置文件不动
start.cmd --no-driver

# 长期：config.json 里 "driver": { "enabled": false }
```

关掉之后：不读状态文件、不写握手文件、不启动状态轮询，右键菜单、拖动、视线追踪、气泡全部照常。

### 换前端怎么办

`config.driver.stateFile` 就是为此存在的。将来要接 WorkBuddy 或别的东西时，只改这一个路径，
新前端只要按那个格式写 JSON 即可——桌宠代码一行都不用动。

真实格式（插件侧产出，桌宠侧消费）：

```json
{ "state": "working", "task": "整理数据", "detail": "editor.js" }
```

其中 `state` 只认这 7 个值：`thinking` / `working` / `waiting` / `success` / `error` / `result` / `idle`，
其余字段自由，`stateMap` 负责把它们映射成表情和姿势。

## 设计要点

### 两条通道，一条免费一条收费

```
状态（免费，0 token）
  DSH 事件 ──► 插件归约 ──► ~/.dsh/live2d/status.json ──► 桌宠轮询 ──► 表情/姿势
                            原子写（tmp + rename），200ms 轮询，无网络无鉴权

动作（付费，按需）
  模型 ──► 插件工具 ──► 读 endpoint.json 拿 url+token ──► 桌宠 HTTP API ──► 气泡/表情/指令
```

**为什么状态走文件而不是 HTTP**：DSH 自己的 Web 端口带鉴权，外部进程直连会 401；插件里注册的路由也只对页面内可用。桌宠是独立进程，所以只能走文件。

**为什么动作走 HTTP**：反向要能立刻送达，文件轮询有延迟；桌宠自己开一个回环端口并写 token，插件读它来鉴权。

### token 开销（实测，cl100k_base）

| | 常驻（每轮都发） |
|---|---|
| 系统提示词 | 104 tok |
| `pet` 工具 | 208 tok |
| `run_shortcut` 工具 | 110 tok |
| **合计** | **422 tok** |
| 对照：FULASKA 版本 | ≈ 897 tok |

单次开销：一句 `say` 约 27 tok，一次快捷指令约 22 tok。
状态投影那条路径 **0 tok**，因为它根本不进 LLM 上下文。

### 参数直驱，不用引擎的 motion / expression 通道

这个模型的 `model3.json` 里没有 `Motions`，也没有 `Expressions` 段（作者只声明了 EyeBlink / LipSync 两个组）。要用引擎通道就得手改 model3.json，等于把程序和这个模型绑死。

而它的 `.exp3.json` 本身就是纯参数表（`key4=1.0` 这种），姿势也只是 `Movement1/2/3` 三个 Add 开关。所以直接写参数：

- 不依赖 model3 结构 → **换模型只要换目录 + 映射表**
- 表情瞬切，没有过渡 → 极简模式天然成立
- 每帧只有几个 `setParameter`，比动作系统轻

代价：exp3 用 Add 混合，"表情互斥"要自己实现。

### 表情可以叠加，只在共用参数时互斥

每个 exp3 实际就是一张「开关表」，实测参数分布极有规律：

| 参数 | 用途 | 谁在用 |
|---|---|---|
| `key1`~`key13` | 表情 / 配件 | 黑脸、流泪、圈圈眼、爱心眼、大牙、加载、钢盆、黑框眼镜… |
| `Clothes1`~`Clothes5` | 换装 | 裙子样式、体型、胸口衣服、鞋、尾巴 |
| `Movement1` / `Movement3` | 姿势 | 狗尾草、竖食指 |
| `LeanInput` | 前倾（物理输入） | 前倾 |

除眼部组（`key3`~`key6`：圈圈眼 / 屑屑眼 / ＞＜ / 爱心眼）之外，各表情碰的参数**互不重叠**。
也就是说「加载(key8) + 尾巴开关(Clothes5)」本来就能共存。

早期那版「切表情时把所有表情参数清零」是错的 —— 它会把用户手动开的尾巴、裙子、体型一起清掉，
表现就是「切个表情，之前设的全没了」。

现在的规则：

- 维护一个「已激活表情」集合，每帧把集合里的参数全部重放一遍
- 激活新表情时，只移除与它**共用参数**的那些（眼部组天然互斥）
- 不共用参数的一律保留 → 可以任意组合
- 右键菜单里表情是**多选勾选**，另有「清除全部表情」

配套两个补充机制（因为个别表情的特效不在 exp3 里）：

- `config.expressionExtras`：给表情补参数
- `config.expressionParts`：给表情补 Part 显隐（exp3 只能动参数，动不了 Part）

### 每帧重放（「表情只闪一帧」的根因）

Cubism 内核每帧会把参数存档/恢复，**只在切换时写一次的话，第二帧就回到默认脸**。
所以每帧重放「已激活表情集合 + 姿势」的全部参数。

用 `set(default + value)` 而不是 `add` —— 每帧都重放，`add` 会无限累加（`ParamAngleZ` 踩过这个坑）。

还有一个连带发现：为了让「前倾」生效（`LeanInput` 是物理输入，physics3.json 里 19 处引用），
参数必须在**物理计算之前**也写一次。这也意味着「帧初读到 default」不能作为唯一判据。

但**不需要手动清零**。实测（`--selftest-clear`）：取消激活「加载」后，`key8` 从 1.00 自动回到 0.00 ——
引擎每帧确实会把参数复位成 default，不写就自动归位。

```
[clear-probe] t=2500ms key8 帧末=1.00  集合 默认体型+加载
[clear-probe] 已取消激活
[clear-probe] t=4000ms key8 帧末=0.00  集合 默认体型     ← 自动归零
```

### 视线平滑

指数阻尼，帧率无关：`k = 1 - exp(-damping × dt)`。
眼珠 `damping=20`、头 `7`、身体 `3.5`——三级错开才有"先看、再转头"的活物感。
指针位置由主进程每 50ms 采样一次全局光标，渲染层再逐帧向目标靠拢，**不是每次采样都直接跳**。

### 窗口几何持久化

位置和尺寸保存在 `pet/stage/.userdata/window.json`（程序自有目录，**不写进 config**）：

```json
{ "x": 60, "y": 60, "width": 700, "height": 1365,
  "configW": 400, "configH": 780, "dpiScale": 1.75,
  "savedAt": "2026-11-02T15:05:25.000Z" }
```

**落盘时机：鼠标释放之后。** 拖动过程中不写盘——100 次移动只关心最后停在哪，
而且高频写会和透明窗口重绘抢 IO。松手（`pet:dragging=false`）立即写一次。
没有 pointerup 的系统级移动（Alt+Space 菜单、任务栏的"移动"）用 700ms 防抖兜底；
退出前再强制刷一次。

**恢复时有两条防漂移措施**：

1. `configW / configH / dpiScale` 记下当时的配置与缩放。配置被人改过就**不沿用旧尺寸**，
   否则会出现「明明改了 width，启动还是老大小」这种没法解释的行为。
2. 位置先 `clampGeometry()` 夹回工作区再建窗口。本机窗口高 1365px，比工作区还高，
   如果 y 用原值，Windows 会在 show 之后自己把窗口推回去（实测 `1000,300 → 1628,295`），
   那次推送由系统决定，位置就漂了。自己夹一次，结果才是确定的。

验证钩子：`node launch.mjs --selftest-drag` 会模拟按住 → 移动 80 次 → 松手，断言
「拖动中未落盘」「松手后落盘且与窗口一致」「尺寸未膨胀」。

### 换模型

1. 把新模型的 `model3.json` + `moc3` + 贴图放进 `model/`（或任意目录）
2. 改 `config.model.dir` 和 `file`
3. 若新模型表情名不同，改 `stateMap` 里引用的名字
4. 眼睛/头部参数名若不同，改 `renderer.js` 里 `idleAngles` / `idleTick` 的 `Param*` 名

新模型必须放在**带 Exp3 目录**的结构里才能自动认出表情；没有表情就只做姿势和呼吸。

## 踩过的坑（都是实测，别重走）

**1. 透明窗口在非整数缩放下「越拖越大」**
175% 缩放下，每次 `SetWindowPos` 都会因内容区/边框区取整把窗口撑大 1~2 DIP。实测拖 80 次：520×780 → 602×861，resize 事件 129 次。`setSize` 强行按回、`setPosition` 代替 `setBounds`、`roundedCorners:false` **全都无效**。
最终解法：启动加 `--force-device-scale-factor=1`，按物理像素创建窗口（尺寸 × dpiScale）。同样 80 次移动，尺寸不变、resize 0 次。

**2. `ELECTRON_RUN_AS_NODE` 会让 electron.exe 退化成纯 Node**
从 Electron 宿主（如 WorkBuddy）继承这个变量时，`require('electron')` 返回 undefined，报「Cannot read properties of undefined」。启动器里必须清掉。

**3. 代理变量重复键会让进程创建失败**
环境里同时有 `HTTPS_PROXY` 和 `https_proxy` 时（Windows 环境变量大小写不敏感），环境块出现重复键，`Start-Process` 直接抛「已添加项」。Node 的 `spawn(env)` 是**重建**环境块，所以启动器用 Node 写而不是批处理。

**4. 大文件下载必须绕开 Clash**
`http_proxy=127.0.0.1:64828` 会把 GitHub Releases 限速到近乎停滞。用 `curl --noproxy '*'`，或镜像（实测 `gh-proxy.com` 1 MB/s > 直连 517 KB/s >> `ghfast.top` 3 KB/s）。

**5. pnpm 的跨盘 `link:` 会生成断链**
跨盘 `link:` 依赖（profile 在 C 盘、插件在 D 盘）会被 pnpm 写成相对路径，解析到不存在的位置。必须改建**目录联接**（junction），它支持跨盘绝对路径。`pnpm install` 后要复查一次。

**6. 角度参数必须写在物理计算之前**
`ParamAngleX/Y/Z`、`ParamBodyAngleX/Y` 在 physics3.json 里既当输入又当输出。在 `beforeModelUpdate`（物理之后）写会被覆盖，表现是「眼珠动、头不动」。要挂在 `beforePhysics` 上。

**7. 浏览器不认裸包名**
`import('pixi.js')` 在页面里会报 "Failed to resolve module specifier"，且 import map 要一路补 `eventemitter3` 等传递依赖。直接用 esbuild 打包成一个 bundle（`npm run build`）最省事。

**8. 批处理文件里别写中文注释**
cmd.exe 按 ANSI 代码页解析 .bat/.cmd，UTF-8 中文注释会被拆成乱命令。启动脚本保持纯 ASCII。

**9. `reg.exe` 可能被安全策略拉黑**
不要用 `reg query` 读 DPI，会被拦。用 `config.window.dpiScale` 承载。

**10. 桌宠被强杀后，`endpoint.json` 会变成「陈旧握手」**
文件还在，但那个端口已经没人监听。插件如果只报 `fetch failed`，模型既不知道是「没开」还是「开过但死了」。
解法：插件读握手后 `process.kill(pid, 0)` 探活（`ESRCH` = 进程已退出），返回「桌宠进程已退出，重新启动即可」。
桌宠侧对应地只删自己写的那份（比对 `pid`），避免把另一个实例的握手文件顺走。

**11. 独立桌宠不该创建别的程序的目录**
最初启动时无条件 `mkdir ~/.dsh/live2d`，于是在一台没装 DSH 的机器上它也会凭空造出这个目录。
改成：**父目录存在才写，不存在就跳过**。目录存在这件事本身，就是「驾驶员在用」的信号。

**12. 表情「切一下就没」——参数必须每帧重放**
Cubism 内核每帧末尾 `saveParameters`、下一帧开头 `loadParameters`。只在切换时写一次，
第二帧就被恢复成默认脸。现在每帧重放「当前表情 + 姿势」的参数表。
探针 `--selftest-expression` 采样帧初/帧末可复现：帧初恒 0、帧末恒 1。

**13. `win.isIgnoringMouseEvents()` 在这个 Electron 版本上不存在**
读它拿到 `undefined`，于是 `!undefined === true`，穿透热键变成单向的（切过去回不来）。
必须自己维护真源（`ignoring` 变量）。手动切换后还要暂停自动判定 3 秒，
否则 50ms 的巡检会立刻把它改回去。

**14. 「体型1 / 体型2」不是两套衣服，是 `Clothes2` 的混合权重**
`0` = 正常头身比，`1` = Q 版（头大身小），作者给的「体型1」是 **0.4**，也就是**两套网格各出一半**。
中间值本来就有穿模风险（衣服和身体如果不是同一套网格，缩放比例不同就会露）。
实测 8 帧连拍 + 「体型1 + 胸口衣服 + 裙子切换」三件叠加，**都没有复现穿模**；
如果看到胸前露肉，多半是早期版本「切表情时全局清零」把 `Clothes3` 之类的换装参数清掉了。
真要改这个值，用 `config.expressionExtras` 覆盖即可。

**15. 「流冷汗」在素材层就是无效的**
`key13`（名字就叫「13. 流冷汗」）能写入、能保持；模型里也有一个 Part 叫「汗」（`Part79`），
但**它的默认 opacity 已经是 1**，把 `Sweat1`/`Sweat2` 拉到 1 也依然看不见汗。
结论：这个 Part 里没有有效网格（导出时丢了或画布外），属于模型素材问题，代码侧无解。

## 交互（2026-11-03）

### 左键点区域

按模型画布归一化坐标划区（`config.json` → `interact.regions`，从上往下匹配）：

| 区域 | 范围 rect [x0,y0,x1,y1] | 行为 |
| --- | --- | --- |
| 头 | 0.30,0.00 → 0.70,0.26 | 随机招呼语 + 随机表情 |
| 裙摆 | 0.24,0.50 → 0.76,0.74 | 长裙 ↔ 短裙（`Clothes1`，-1=长裙） |
| 腿 | 0.36,0.74 → 0.64,0.96 | 招呼语 |
| 尾巴 | 0.04,0.60 → 0.28,0.86 | 招呼语 |

未命中任何区域时也走招呼语。左键拖动窗口的老行为保留（移动超过 3px 算拖动，不算点击）。

### 右键：短按开菜单 / 长按进编辑

状态机（`app/interact.js`）：

```
idle ──右键按下──> pressing ──<500ms 松手──> idle（弹出胶囊菜单）
                     └──≥500ms──> sweeping ──加载条扫 360°──> edit
```

- **短按（<0.5s）**：弹出胶囊菜单。独立透明窗口，贴在模型右侧；右侧放不下自动换左侧，再放不下夹回屏幕内。
- **长按（≥0.5s）**：指针位置出现「加载」放射短条，`conic-gradient` 遮罩从 -90° 扫到 270°（0.5s），扫完进入编辑模式。
  - 松手不会打断扫过，动画走完照样进编辑。
- **编辑模式**：窗口内显示**圆角 18px** 的蓝色虚线框，左上角浮出「拖动调位置，拉边框调尺寸」2.6 秒。
  - 拖动：框内任意位置拖（左键或右键都行）
  - 缩放：指针离**虚线框线** 28px 内 → 光标变双箭头，等比缩放，锚点固定窗口中心，范围 `scaleMin`~`scaleMax`（0.45~2.2）
  - 判定基准是框线，不是窗口边缘 —— 之前按窗口边缘算，导致「点在框上没反应、点在框里面反而能拉」。
  - 框线的任意一段（四条边 + 四个圆角）都能抓，所以不需要四角手柄。
  - 框离窗口边多远由 CSS 变量 `--frame-inset` 定（6px），`interact.js` 读同一个值，改一处即可。
  - 退出：完成一次拖动/缩放后松手，1 秒无操作自动退出
  - 特例：长按后**原样松手没动过** → 虚线框常驻，直到真的完成一次位置/尺寸调整才开始 1 秒倒计时
  - 编辑期间主进程暂停自动穿透（`editMode`），否则指针移到角色剪影外就会丢事件

### 对话气泡（胶囊风格）

跟右键菜单同一套视觉语言，但**底色浅一档**（`rgba(236,243,255,.96)` 对菜单的纯白），
这样气泡和菜单同时出现时气泡退后一层，不抢注意力。

- 形状：`border-radius: 999px` → 多行时是「变胖的胶囊」，两端始终半圆
- 星纹：复用菜单那张 26px SVG（对角两星），`fill-opacity` 压到 0.42
- 描边：`inset 0 0 0 2px rgba(86,134,254,.55)` + 内发光
- 文字：`#2f5aa8`，字号走 `--bubble-font`（= 配置字号 × UI 缩放）
- **尾巴朝下**（气泡在头顶，说话的人在下面），用 SVG 画 28×16 的三角：
  填充一支 `#ECF3FF`，只描两条斜边、顶部留空 —— 于是斜边和气泡底边的蓝线
  在同一个点相接，看起来是一根线拐下去又拐回来。
- 三个踩过的坑：
  1. border 三角是独立多边形，颜色再接近也有接缝，像「贴了个箭头」；
  2. 旋转 45° 方块露出的是半圆包，不像尾巴；
  3. 尖端用 Q 曲线收会在 28×16 的尺寸下变成一颗小圆球 —— 用直线尖 + `linejoin:round` 即可。
- **投影必须用 `filter: drop-shadow`，不能用 `box-shadow`**：后者画在盒子外侧，
  正好盖在尾巴上，把尾巴染成一块比气泡深的色块。

### 进入编辑模式的小反馈

- 气泡说一句「有框？？」
- 表情切成 `＞＜`
- 退出时把表情**还原成进来之前的样子**

还原用的是「拍快照 → 退出时 clear + 按原顺序重放」，不是「只删 ＞＜」：
`＞＜` 是眼型表情，激活时会把原来的眼型挤掉，光删它回不来。
快照只在第一次进入时拍（`editExprSnap` 非空就跳过），反复进出不会把 ＞＜ 记进去。

### 胶囊菜单

- 尺寸：胶囊 84×330，圆角 42（完美半圆），星纹 26px 一格，字号 30px，间距 15，外留白 18
- 星纹是 `background-repeat` 的固定尺寸图案 —— 宽度动画时**不缩放、不跳位**，视觉上是跟着抽屉一起被抽出来
- 每个胶囊的动画：
  - `0 → 100ms`：以小圆形态浮现（opacity 0 → 1）
  - `100 → 400ms`：宽度 84 → 330 展开（`cubic-bezier(.22,.86,.25,1)`），文字同步浮现
  - 相邻胶囊间隔 100ms
- 菜单项在 `config.json` → `interact.menu`，`action` 取值：`skirt` / `expr-random` / `pose-cycle` / `open-config` / `toggle-through` / `quit`

### 设置页（`app/settings.html`）

独立 BrowserWindow，尺寸 = 工作区 70%，居中。右键菜单 →「打开设置」进入（`action: open-settings`）。

**出场动画**：0~0.1s 在角落浮现一个 150px 的圆，0.1~0.3s 展开到整窗，圆角同步收到 28px，0.3s 内容淡入。
起点角落看舞台在屏幕哪一侧 —— 在左从左下角长出来，在右从右下角，所以窗口感觉是「从人物那边推出来」的。

**DPI 补偿（关键）**：窗口按物理像素建（`--force-device-scale-factor=1`），
所以 15px 的字在 175% 屏上只有 8.6 个逻辑点，小到看不清。
`body` 的 `zoom` = 用户倍率 × 系统 DPI，1.0× 时视觉大小才和主窗口气泡一致。

**三个主题色**：

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `--ui-bg` | 背景 | `#FFFFFF` |
| `--ui-star` | 星纹 | `#E6EFFF` |
| `--ui-edge` | 边框 | `#5686FE` |

星纹不能写死在 SVG data URI 里（改不了色），用 **mask + `background-color`**：
mask 只取形状，颜色由变量给。滑块把手同理 —— data URI 里没法写 `var()`，
所以由 JS 按 `--ui-text` 重新生成一份。

**底纹只有一层（关键）**

星纹由 `.sheet::before` 在整张卡片上铺一次，**所有胶囊都是透明背景 + 只画边框**，
图案透过胶囊继续走，所以是连续的。早期版本让每个胶囊各自铺一份 `background-image`，
结果是每进出一个胶囊图案就错位一次 —— 视觉上像拼接。

同理，**边框必须单独一层**：`.sheet` 自己的 `inset box-shadow` 会被 `::before`（星纹）
盖掉，尤其在深色主题下边框会缺一截。所以边框拆到 `.sheet::after`（`z-index:3`，
`pointer-events:none`），压在星纹和内容之上，且**用 `border` 不用 `box-shadow`**。

**圆角外要干净透明，有两样东西必须去掉**：

1. **卡片外投影**（`box-shadow: 0 18px 60px …`）。窗口是透明的，投影会画到圆角外侧
   那四个小三角区域里，看着就像「外面还蒙了一层」。层次感靠边框本身给，别用阴影。
2. **第二圈 `inset` 淡边**（`inset 0 0 0 3px` 那种内光环）。它在圆角处会多糊一层
   半透明，叠加 border 自己的抗锯齿，边缘就毛了。

实测：改完后从角点斜向每 2px 采样，`d=0~12` 全为 `alpha=0`，`d=14` 才是边框的抗锯齿。

**控件**（全部无填充、只有边框）

- 复选框：四角星，空心（描边）/ 实心（填充）两张 mask 切换，40px
- 文本块：胶囊，右侧 `linear-gradient` mask 淡出
- 滑块：无填充胶囊轨道 + 星星把手
- 颜色选择器：胶囊内嵌圆形色块（色块本身是实色，那是颜色预览），点击唤起系统取色器
- 绑定对话：1~9 占位，**滚动边缘动态渐隐**（见下）

**滚动渐隐**不用固定某一项：那样只对初始位置成立，用户一滚就假了。
改成量 `scrollTop` 动态生成容器的 `mask` —— 到顶不遮上边、到底不遮下边，
永远只有「正滑出视口的那几项」在淡。滚动条全程 `display:none`，靠渐隐本身暗示可滑。

**尺寸是配套的**：菜单项 46px / 间距 8 / `max-height: 348`，频率胶囊 52，行内边距 14。

## 动作优先级（2026-11-03）

```
0  LLM 输出的动作反馈脚本
1  用户主动交互（点头 / 摸裙摆 / 菜单）
2  随机事件触发的动作/表情变化（含会话状态投影）
3  鼠标追踪（持续层）
```

- **0 和 1 合并成一档**：定义就是「不互相冲突，谁先触发谁先播」，合并后天然不互抢。
- **2 不能打断 0/1**：低档请求直接丢弃（不排队 —— 等轮到它时语境早变了）。
- **3 不进队列**：眼珠/头部的阻尼追踪是持续层，任何动作都能盖住它。

实现是「通道 + 租约」（`app/renderer.js` 的 `claim()`）：

| 通道 | 内容 | 冲突策略 |
| --- | --- | --- |
| `face` | 表情 | 租约 1.5s，同档/高档可接手 |
| `pose` | 姿势 | 租约 = 补间时长 + 260ms |
| `bubble` | 气泡 | 真队列，前一句念完再念下一句（超过 6 条丢最早的） |

日志里能看到判定结果，例如：

```
[act] face 正被 P0 占用，丢弃 P2 的请求     ← LLM 在演表情时，状态投影抢不到脸
```

## 拖动：只剩编辑模式一条路（2026-11-03）

左键不再拖动窗口，只做点击交互（摸头 / 裙摆 / 说话）。移动窗口统一放在
「右键长按 0.5s → 编辑模式」里，拖动和缩放都在那儿。

**闪烁的两条根因**（都在主进程 `moveTo`）：

1. **一帧发两次 SetWindowPos**。渲染层 rAF 跑 120fps，屏幕多半 60Hz，一个合成周期里
   连发两次，DWM 会把上一帧的合成结果留在旧位置 —— 看起来就是「形象在别处闪一下」。
   现在按 `displayFrequency` 对齐合并，一帧最多移一次。
2. **移动路径里碰尺寸**。老代码每次移动都 `getSize()`，不等于基准就 `setSize()` ——
   那是 175% DPI 下「越拖越大」的补丁。现在尺寸只由 `applyResize` 改。

## 与 DSH 的通信方式

**是本地回环 HTTP，但不是固定端口。**

- 桌宠启动时用 `server.listen(0, '127.0.0.1')` 让系统分配一个**空闲端口**
  （每次启动都不同，实测 52031 / 60466 / 64874…），只绑 `127.0.0.1`，外网进不来。
- 端口和 token 写进**握手文件** `~/.dsh/live2d/endpoint.json`
  （`{url, token, pid, shortcuts}`）。插件每次调用前重新读它，
  并用 `process.kill(pid, 0)` 确认桌宠还活着 —— 所以「没开」和「开过但崩了」
  能给出不同的提示，而不是一句 fetch failed。
- `/api/*` 要求 `x-stage-token` 头，token 是每次启动随机生成的 36 位 hex；
  静态资源（页面、模型、贴图）不校验，因为它们本来就在本机。
- 反方向（会话事件 → 状态）不走网络：插件把事件就地归约成
  `~/.dsh/live2d/status.json`，桌宠每 200ms 轮询这个文件。零 token。

```json
// ~/.dsh/live2d/endpoint.json
{ "url": "http://127.0.0.1:65093", "token": "…", "pid": 41800, "shortcuts": ["open_control", "…"] }
```

**注意本机的一个坑**：安全策略禁止 `electron.exe` 往 `C:/Users/...` 写
（连新建空文件都报 `EPERM(-4048)`，`node.exe` 写同一路径完全正常，
`electron.exe` 用 `ELECTRON_RUN_AS_NODE=1` 跑也一样被拦 —— 拦的是这个二进制）。
所以握手文件改由**启动器**（node 进程）把 `.userdata/endpoint.json` 镜像过去，
原子替换（写 `.tmp` 再 rename）。舞台自己写的那份仍然保留，正常机器上两边都写，
内容一致。

## 动作序列：抄上游的做法（2026-11-03）

翻了上游那个开源项目（`_upstream/app-src/src/stage`），结论是：

**它不是「动作1,0.3秒、动作2,5秒」的播放列表，而是「关键帧存档 + 本地补间」。**

`actions.json` 里一个动作长这样（`bridge/lib/index.js` 的 `live2d_actions` 可读写）：

```json
{ "id": "…", "name": "伸懒腰", "duration": 4200,
  "params": ["ParamAngleY", "ShoulderY", "…"],
  "keys": [ {"t": 0, "values": {…}}, {"t": 1260, "values": {…}} ],
  "lines": ["伸个懒腰……"] }
```

- `keys` 是**绝对毫秒**的关键帧，每个关键帧给一批参数值；
- 待机动作（`idle-motions.js` 的 `ROUTINES`）写成 `tracks: { 参数: [[t, 增量], …] }`，
  t 归一化到 0~1，**值是增量不是绝对值** —— 所以能和视线、表情、姿势叠加，
  首尾都归零，接得上下一段；
- 播放端每帧 `sample(keys, p)`，段内用 `smoothstep (t²(3-2t))` 插值。
  **LLM 只写关键帧和时长，中间帧全在本地算** —— 这就是「平滑」的来源。

我们照这个做了 `motions`（`config.json`）：`{ ms, tracks: { 参数id: [[t, 增量], …] } }`，
内置 5 个（重心换脚 / 东张西望 / 伸懒腰 / 打瞌睡 / 抖尾巴，数值取自上游）。
播放器是 `renderer.js` 的 `playMotion()` / `applyMotion()`：每帧采样后
**加到当前值上**（`param.add` 的量级），调用点在 `idleAngles()` 之后 ——
视线先写、动作再叠，谁也不覆盖谁。

LLM 侧两个入口（`pet` 工具，`kind: "motion"`）：

```jsonc
{ "kind": "motion", "name": "伸懒腰" }                      // 内置动作
{ "kind": "motion", "ms": 2000,                            // 现编的关键帧
  "tracks": { "ParamAngleY": [[0,0],[0.4,10],[0.7,10],[1,0]] } }
```

`tracks` 走 `POST /api/motion` 的同一份结构，所以模型可以自己「编一个歪头动作」。

## 多步序列与自定义预设（2026-11-03）

单动作 + 单表情能凑出表演，但**组合起来要模型连着调好几次 `pet`** —— 而每次调用都是一次
新的 `claim()`：前一个动作还在演，后一个按同档规则接手，中间的空档和互相打断都由时序决定，
模型既看不见也控制不了。所以加了一条「整段交出去」的路径。

### 序列：`kind: "sequence"`

```jsonc
{ "kind": "sequence", "steps": [
  { "op": "expression", "name": "爱心眼" },
  { "op": "motion", "name": "伸懒腰" },                    // 默认等它演完（查 config.motions 的 ms）
  { "op": "say", "text": "搞定啦" },                        // 气泡只等 2600ms，下一句不用干等 9 秒
  { "op": "pose", "name": "chest", "after": 500 }          // after 显式覆盖
] }
```

**调度放在舞台侧**（`lib/sequence.mjs`），不放在插件侧。只有舞台知道每一步真实多长：
动作的 ms 在 `config.motions` 里，姿势补间 260ms，气泡默认 9s。插件只能猜，猜早了下一步
会被 `claim()` 丢掉，猜晚了中间就有空拍。

- `op` 五种：`say` / `expression` / `pose` / `motion` / `wait`（`wait` 不发事件，只占时间）。
- `after` 是「这步发出去之后等多久」，不是「这步完全结束」—— 气泡可以一边念，动作一边接上来。
- 上限 24 步 / 120 秒；同一条新序列会**顶掉**正在跑的旧序列（排队没有意义：等轮到第二条，
  语境早就变了，和随机事件不排队是同一个理由）。
- `stop` 只打断后续步骤，正在演的那一下让它自然演完 —— 硬切会把参数停在半路的增量上，看着像抽搐。

### 预设：存在插件目录，不存握手目录

```jsonc
{ "kind": "preset", "op": "save", "name": "打招呼", "desc": "有精神地招手",
  "steps": [ … ] }                                    // 和 sequence 的 steps 一模一样
{ "kind": "preset", "op": "play", "name": "打招呼" }
```

路径是 `<插件目录>/data/presets.json`，**不是 `~/.dsh/live2d/`**：

- `~/.dsh/live2d` 是「桌宠 ↔ 插件」的握手区，里面的东西两边都可能写，卸载插件时也没人负责清；
- 预设是插件的用户数据，该跟插件同生共死。安装时建的是指向 `bridge/` 的目录联接，
  删掉插件就是一锅端，机器上不留没人认领的文件。

保存的是 steps 原文，播放时原样转发给 `/api/sequence`，中间不做任何结构转换 ——
存的和播的必然一致。上限 40 条，名字 ≤ 24 字；`save` 覆盖同名（保留播放次数）。

### 自述的写法

工具描述就是模型的全部说明书，所以三件事必须写进去：

1. **什么时候用 sequence 而不是连调几次 pet** —— 不写它就会连着调；
2. **`tracks` 能写哪些参数** —— 509 个参数里只有 10 个是安全的（其余被物理接管或破坏形状），
   不列出来它就会去试 `ShoulderY`；
3. **`v` 是增量不是绝对值** —— 不强调就会写成绝对值，动作结束时参数停在半路回不去。

注意区分两类信息：**运动学约定**（tracks 参数、增量语义）写死在参数描述里没问题 ——
那是这套播放器的设计，不随模型变；**选项名单**（哪些表情/姿势/动作存在）绝不能写死，
必须走下面的 catalog 注册。

代价是常驻 token：`pet` 工具 ~400 tok（含名单与预设清单）。

### 能力名单：舞台注册，动态更新（2026-11-03）

表情 / 姿势 / 动作的合法名单**只有舞台知道**（表情来自模型 Exp3 扫描，姿势/动作来自
`config.json`），插件不再维护第二份清单：

- 舞台提供 `GET /api/catalog`；
- 插件启动时拉一次、每次调用 `pet` 时顺手刷新（30s 防抖，不阻塞表演）；
- 名单或预设变化 → 同名重新注册工具，模型下次看到的就是新清单；
- 拉不到（桌宠没开）时退回内置兜底名单，工具描述不至于空白。

配套的名字策略（都在舞台侧执行）：

| 输入 | 行为 |
| --- | --- |
| 不存在的**动作**名 | **忽略**（单次返回 `ignored`；序列里跳过该步并回报 `skipped`）—— 模型常即兴起名，不值得打断对话 |
| 不存在的**表情/姿势**名 | 400 + 完整 `available` 清单 —— 那两个是明确的选项列表，传错就是该修的错 |

### 手臂动画必须走原生 motion 通道（2026-11-03）

实测：让模型自己编 `tracks` 动手臂（RArm/RForearm…），手臂纹丝不动。三层原因层层排查：

1. **手臂参数不是角度**：`RArm/LArm/RForearm…` 的量程是 **-1~+1**，是物理摆动的
   修正量，不是姿势驱动 —— 写 25 直接 clamp 到 1，视觉上仍然看不见；
2. **它们全是物理输出**（physics3.json 输出表 200+ 项），直驱写入会被物理结果覆盖；
3. **决定性对照**：把同一动画（`Animation/竖手指切出来动画.motion3.json`）注册进
   model3.json 的 `Motions.arm` 组，走引擎**原生 motion 通道** —— 手臂抬起、食指
   竖起，完全正常。参数直驱写同样的值无效：引擎 motion manager 每帧
   `loadParameters()` 恢复快照，直驱值在渲染管线里被冲掉。

**方案**：`Animation/*.motion3.json` 注册为 model3.json 的 `Motions.arm` 组，
main.cjs 启动时读该组建「原生动画表」（名字 = 文件名，时长 = 动画 Duration），
并入 `motionCatalog` —— `/api/motion`、`/api/sequence`、catalog 里它们和关键帧
动作**同名同权**，渲染层命中动画表就走原生通道。

配套：播放原生动画期间姿势层让位（`animationHold`）—— 原生动画会 overwrite
Movement1/3 这些姿势参数，姿势层每帧重写会把动画的手臂位打回去。

现在模型可以直接：`{ "kind": "motion", "name": "竖手指切出来动画" }`，或放进
sequence 与说话、表情组合成完整表演。


### 表演时冻结鼠标追踪（2026-11-03）

实测问题：LLM 动作明明在播，画面上看不见。原因：追踪每帧把头写成 ±30°、身体 ±14°，
动作增量只有 ±3~6° —— 数学上叠加，视觉上被追踪的变化整个淹没。

修复（`renderer.js`）：播**表演层**动作（LLM / 用户交互，PRIO 0/1）时冻结追踪对
头 / 身体 / 眼珠的写入，演完 +400ms 后阻尼自然把视线收回鼠标，不会跳。
随机待机动作（PRIO 2）保持原设计 —— 它本来就该能被追踪盖住。



## 气泡独立成窗口（2026-11-03）

气泡原来画在舞台里，`max-width: 88%` 是相对舞台的 —— 舞台缩到 394px 时，
一句话被切成五六行。现在它是独立透明窗口（`app/bubble.html`）：

| 项目 | 值 | 说明 |
| --- | --- | --- |
| 高度 | `min-height: 84px` | 和右键菜单胶囊同高，两个 UI 同一套比例 |
| 字号 | 22px | 比菜单的 30 小一档：气泡常有一二十字，30 号会顶到 3~4 行 |
| 排版宽度 | `max-width: 420px` | **与舞台尺寸无关**，舞台再小也不影响换行 |

- 尺寸在页面里量（`getBoundingClientRect`）→ 回传主进程改窗口大小 → 再淡入，
  顺序反了会看到窗口先大后小跳一下。
- 位置贴在人物头顶；**尾巴横向位置按「头顶中心在气泡窗口里的 x」算**，
  再夹到两端圆角内侧 —— 气泡被屏幕边夹住时尾巴也不会指向空气。
- 窗口 `focusable: false` + `setIgnoreMouseEvents(true)`，永远不抢焦点、不挡鼠标。

## 编辑模式手感修正（2026-11-03）

- **长按到扫过结束、手还没松 → 直接进入拖动**（`beginDrag()`）。以前必须松开再按一次。

  左边框 `-dx`、右边框 `dx`、上边框 `-dy`、下边框 `dy`，取其中最大的一条。

## 已知问题：原生手部动画无限循环（2026-11-03）

**现象**：`Motions.arm` 通道的原生动画（竖手指切出来动画 / 竖手指切回默认 /
举手切默认手 / 默认手切举手 / 狗尾草切换出来 / 狗尾草切回默认手 / 脱捕）
播放一次后**不会停在结尾姿态**，而是每 ~1.25 秒从头重播同一套「切换」动作，
手臂无限循环。

**根因链**（四层逐一定位，均经代码验证，含当前运行的 bundle）：

1. **文件层**：`model/Animation/*.motion3.json` 8 个文件的 `Meta` 全部是
   `"Loop": true`（Cubism Editor 默认残留）。其中 7 个一次性切换动画本应是
   `false`；只有 `IDLE` 是合理循环。
2. **调用层**：`renderer.js` 的 `playAnimation()` 调
   `stage.motion('arm', index, { onFinish: finish })` —— **没传 `loop`**。
3. **适配层**：`engine.js` 把 `loop: undefined` 透传给 `model.motion()`。
4. **引擎层**：`untitled-pixi-live2d-engine`（`dist/cubism.js:8659` 加载时把
   `json.isMotionLoop()` 读进 `_motionData.loop`；`cubism.js:9202`
   `motion.setLoop(loop != null ? loop : motion._motionData.loop)`）——
   调用方不传值时**回退到文件自带的 `Loop` 元数据**。其文档注释明确说
   传入的 `loop` 才是 "Overrides … motion JSON loop metadata when specified"。

**循环的两个后果**：

- `cubism.js:8341-8348`：keyframe 时间回卷 `while (time > duration) time -= duration`
  —— 每 1.25 秒整段重播；
- `cubism.js:8448-8450`：循环时走 `updateForNextLoop`，`onFinishedMotion`
  **永不触发** → `playAnimation` 的 `onFinish` 落空，姿势层解冻只能靠
  `setTimeout(finish, info.ms + 800)` 兜底（~2s 后）。届时姿势/表情层恢复
  每帧重写参数，而动画仍在循环 —— 两层在画面上互抢参数。

**修复方向**（本次未实施，只记录）：改任一处即可，两处都改更稳：

1. 数据侧：7 个切换动画的 `Meta.Loop` 改 `false`（`IDLE` 保持 `true`）；
2. 代码侧：`playAnimation()` 显式传 `loop: false`（引擎明确支持，且优先级高于文件元数据）。

## 已知问题：身体频繁「抖动」，后端空闲也不停（2026-11-03）

**现象**：身体持续做细小的倾斜/抖动，与后端会话状态无关——后端回到空闲后依然不停。

**结论**：主体是既有的「身体跟随鼠标光标」行为，不是 0.2.0 新增 bug；叠加上一节的手部动画无限循环后，「不停」的感觉被放大。

**机制**（代码逐层验证）：

1. 主进程每 50ms 采样全局光标（`main.cjs`：`screen.getCursorScreenPoint()`），
   以半个屏幕为半径归一化到 -1..1，发 `pet:gaze`。这条链路与会话状态文件、
   `applyState` 完全无关。
2. 渲染层每帧用指数阻尼向目标靠拢（`renderer.js dampGaze`，帧率无关）：
   - `GAZE.dampingBody = 5` → 身体时间常数 ~0.2s，跟随较快；
   - `GAZE.curve = 0.7` → pow<1，很小的鼠标位移也会产生不小角度；
   - `GAZE.deadZone = 0.02` → 只过滤约 2% 半屏宽（2560 屏约 25px）的微动，
     基本不过滤；对比 `dampingEye = 22` / `dampingHead = 11`，身体是三层里
     最慢但仍持续追。
3. `idleAngles()` 每帧（onFrame 与 beforePhysics 各一次）**绝对写入**身体角度，
   只受 `gazeHoldUntil` 门控（仅在 keyframe motion 播放窗口 ms+400 内冻结为 0，
   原生手部动画播放期间**不冻结**）：
   - `ParamBodyAngleX = gazeState.bodyX * 14 * bodyGain` → 身体左右跟随 ±14°；
   - `ParamBodyAngleY = gazeState.bodyY * 10 * bodyGain` → 身体俯仰跟随 ±10°；
   - 同帧还写头 `ParamAngleX = headX*30`、`ParamAngleY = headY*24`。
4. 这些角度参数同时是物理链输入（physics3.json：头发、耳朵、裙子跟随身体动），
   感知上的「抖动」被毛发/裙摆进一步放大。

**为什么「后端空闲也不停」**：光标跟随由主进程全局光标采样驱动，会话空闲只停
`applyState`（表情/姿势层），不停光标链——鼠标一动身体就跟随，与后端无关。

**加剧因素（本次会话）**：上一节的手部动画无限循环仍生效，最后播放的原生动画
（本次为「脱捕」）持续循环，手臂不静止；keyframe motion 不会取消它（舞台端没有
任何停止 arm 动作的路径），与身体跟随叠加。

**调参方向**（不改代码）：

- `config.json → idle.bodyGain`：1.0 → 0.4~0.5，身体倾斜降到 ±5.6°/±4°；
  置 0 则身体完全不跟随（写入恒 0），眼神/头部跟随保留；
- `idle.headGain` 同理作用于头部；
- `GAZE.dampingBody` / `GAZE.deadZone` 写死在 renderer.js（代码侧），config 调不到——
  若要「只追大动作、忽略小抖动」需改代码：`dampingBody` 5→2、`deadZone` 0.02→0.08。
